# Lessons

One line per miss: the class, and the mechanism that now catches it.

- 2026-09-22 — A reproducibility claim was tested on the coarsest output (support) and hid drift in branch lengths and lnL; claims are now tested on every number a caller would compare, across fresh processes, with a frozen-clock positive control (`tests/test_support.py`).
- 2026-09-22 — The refusal wrapper converts only `ValueError`, and cogent3/piqtree report bad input as other types, so user errors surfaced as opaque crashes; errors are now classified at the input-parsing boundary, and `tests/test_input_boundary.py` asserts every known library input error carries its reason through a real MCP session.
- 2026-09-22 — `validate()` kept its own copy of the alphabet and it drifted from cogent3's; it is now derived from cogent3, and a test compares the two on every printable character.
- 2026-09-22 — A test asserted `ready_for_infer_tree is True` for output `infer_tree` refuses, encoding the bug; "ready" is now computed by `infer_tree`'s own checks.
- 2026-09-25 — `rank_models` trusted that a dict iterated once per model, but piqtree re-adds the best models under non-string keys, so the winner was ranked as its own runner-up; names are collapsed at the boundary with a disagreement check, and `tests/test_models.py::test_each_model_is_ranked_once_and_never_its_own_runner_up` checks uniqueness on real engine output.
- 2026-10-18 — A docstring said tool calls were serialised on the event loop, but MCPServer runs sync tools in worker threads, and piqtree's per-call chdir/fd swap interleaved into a deleted cwd; calls now take a process lock, and `tests/test_concurrent_calls.py` fires six engine calls at once in one server.
- 2026-10-18 — `model_finder` was trusted to return whenever IQ-TREE did, but piqtree re-parses the winners' names and rejects some IQ-TREE emits (bare `K3Pu`); statistics are read from the raw output, tested against piqtree's own call and on the benchmark alignment that broke it.
- 2026-10-24 — `analyze.py --as-written` wrote the secondary tables over the primary ones in the same directory, so whichever rule ran last owned `summary.tsv`, and only a stdout line said which. The secondary rule now writes to `<outdir>/as_written/`, and `tests/test_agent_qa_controls.py::test_the_as_written_tables_never_overwrite_the_primary_ones` was seen to fail on the old code. Same review: the PREREG promised a billing check that `run.py` does not hold; it lives in the external wrapper, and the PREREG now says so. Not hookable: whether a sentence in a PREREG names where its rule is enforced.
- 2026-10-25 — `bootstrap.py` said piqtree 0.8.3 did not expose UFBoot support, on a check of node names and `params` only; cogent3 puts a numeric internal label in `.support`. The absence claim kept the server on a nonparametric loop that cost 25-93 s per replicate, and the field benchmark aborted all 10 of its 89-taxon runs. UFBoot2 is now read from `.support`, failing loud if it is missing, and `tests/test_support.py::test_ufboot_separates_the_false_clade_and_calls_it_unsupported` checks it on a wrong tree. Not hookable: whether an "X does not expose Y" comment looked at every attribute.
- 2026-10-25 — Tools were silent for a whole call, so a client idle timeout could not tell working from hung. Every tool now heartbeats through `notifications/progress`, and `tests/test_mcp_protocol.py::test_long_calls_send_progress_so_a_client_idle_timeout_does_not_fire` checks it on a real stdio process, including a call queued behind the lock. It was seen to fail (0 notifications) on the old server.
- 2026-10-25 — The heartbeat assumed every Context had a request, and raised out of the call while its engine work ran on, so the orphan raced the next call's piqtree fd swap: 263 errors in one suite run, after a run under less load had passed 214 of 214. Calls without a request now skip the heartbeat, and a failed send joins the work before raising. `tests/test_concurrent_calls.py::test_queued_in_process_calls_survive_the_heartbeat` (a 0.01 s interval, so the path always fires) and `::test_a_failing_heartbeat_fails_the_call_only_after_the_work_is_done` were seen to fail on the old code. Class: a code path that runs only past a timer, which one passing run under light load never reached; a timer-gated path gets a test that sets the timer to ~0.
- 2026-10-25 — `ufboot_tree` keyed support by canonical split and assumed one edge per split, but at a root bifurcation two edges canonicalise to the same split and the Newick writer labels only one, so a correct tree read as "no UFBoot support" or had its value overwritten. Caught by PR review, not a test: every fixture was rooted at a polytomy. `support_by_split` now takes a split's value from whichever of its edges is labelled and refuses two different labels, and `tests/test_support.py::test_ufboot_support_reads_a_root_bifurcation_from_whichever_edge_is_labelled` was seen to fail on the old code. Class: a map keyed by a canonical form assumes the form is one-to-one with its source; any canonicalising key gets a test with two sources that collide. Not hookable.
- 2026-10-26 — The leak scan's `RUN_DIR` modelled a run's dir as it was created (`phyloqa-alt-6alf_1m7`) and never as Claude Code writes it back (`-tmp-phyloqa-alt-6alf-1m7-cwd`, for background-task and saved-output folders), so a run's own path flagged it invalid (confirm alt p2q03, p3q07; pilot mcp p3q09). It now matches tempfile's 8-character suffix in either form, and `tests/test_agent_qa_controls.py::test_the_runs_own_dir_in_claude_codes_dashed_form_is_not_a_leak` uses paths copied from a real transcript and failed on the old code. Class: a pattern over another program's output, written from our own naming; the check is a rescan of the real transcripts, old rule vs new. Not hookable.
- 2026-10-30 — The nightly's mutation timeouts in `ufboot_tree` were read as slow mutants (repo-template triage, 2026-10-25 and 10-30), but they were mutmut's default `fork` isolation: the stats and clean passes run IQ-TREE in mutmut's own process, and a forked child that calls IQ-TREE again hangs until the time limit. 185 timeouts on 2026-10-30, about 70 mutants a night, and the hangs hid real survivors. `[tool.mutmut] process_isolation = "forkserver"`; on mutants 1-19 the old setting gave 8 timeouts and the new one 0 (6 survived, 2 killed), and mutants 1-3 run alone under plain pytest passed in 17-18 s while killed mutant 5 failed. Class: a harness verdict ("timeout") taken at face value; the check is to rerun a few in one process outside the harness. Not hookable.
- 2026-11-03 — 18 of `ufboot_tree`'s mutants survived the nightly (2026-11-02): its default seed and moltype, its own replicate check, the seed it hands IQ-TREE, the clade order, `in_ml_tree`, the reported seed and the coverage check's message. Every test reached it through `infer_tree`, which validates first and always passes `seed` and `moltype`, so the wrapper hid the function's own contract. `tests/test_ufboot_tree.py` calls it directly; all 18 mutants, run alone with `mutate-run`, fail it. The seed is checked at the engine call, not by comparing two runs: IQ-TREE is not bit-exact at one seed (E|F 0.80 then 0.75 in one process), so a lost seed and the wall clock look the same. Class: a function tested only through a wrapper that pre-validates and fills every argument; its survivors are the report. Not hookable.
- 2026-11-04 — `support_method="ufboot"` shipped (0.8.0) with the reproducibility claim measured on the nonparametric bootstrap: drift 0.05 and an exact seeded resampling. UFBoot2's replicates are drawn inside IQ-TREE's clock-dependent search, and its support moved 0.12 across 48 fresh processes; an agent on the field benchmark passed the 0.05 on to its user. A claim measured on one method was reported for every method added after it. The claim is now keyed by method, a method with no measurement is refused, and each method has its own fresh-process test against its own claim plus a frozen-clock control (`tests/test_support.py`).
- 2026-11-05 — 76 mutants survived the nightly in four input checks (`restrict_models`, `map_positions`, `_check_rows`, `_two_trees`), the same class as `ufboot_tree`'s 18: `restrict_models`' empty check is pre-empted by `select_model`'s own and was never reached, the tests matched a message fragment (`match="models is empty"` passes on "XXmodels is emptyXX"), and the Newick parser ignores text after a tree's ';', so a wrong `_two_trees` suffix was invisible through `compare_trees`. `tests/test_restrict_models.py` and `tests/test_map_positions_contract.py` call the functions directly and compare full messages; 75 of 76 fail under `mutate-run`, the 76th (`?` exemption) is equivalent because cogent3 accepts `?`. Class: a partial-match assertion and a forgiving downstream parser hide the function's own output. Not hookable.
- 2026-11-05 — All 42 of `map_column`'s mutants survived the nightly (2026-11-05): the tests asserted `column` and `rows` and never the whole result, so the window (its bounds and slices), the `query` echo, the first and last columns, the 20-name cut-off and every refusal message could change unseen. `tests/test_map_column.py` compares the full returned dict against a hand-planted alignment (letters, one per column) and each refusal in full; 42 of 42 fail under `mutate-run`. Class: asserting chosen fields of a returned dict leaves every other field unguarded. Not hookable.
